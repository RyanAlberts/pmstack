# Framework first, examples second

The opening screen teaches why evaluations exist and how a task becomes evidence for a decision. It does not select a sample agent or imply a prepared result is a live trial.

A restrained green and paper palette separates the work surface from contextual explanations. Large editorial type carries the premise: the PM defines success. Numbered navigation follows the craft of authoring an evaluation. Examples appear below the framework with persistent labels.

The first action defines the customer's job and target. Guidance adapts to single-response models, coding agents, conversational agents, research agents, computer-use agents, and long-running teammates. Every target uses the same task, environment, trial, evidence, and grader structure.

Task and grader forms retain the relationship between a requirement and its measurement. Reference checks teach the difference between internally consistent expectations and observed agent performance. A false completion claim without outcome evidence stays unresolved.

The results interface preserves the distinction between agent failure, evaluation failure, and insufficient evidence. Human grades are explicit review actions. Diagnostic notes never silently rewrite a score.

The browser and terminal share one grading engine. A suite contains data; a separately configured adapter supplies executable commands. JSON and Markdown carry work between tools. No provider or proprietary browser session is the source of truth.

The old customer-problem recommendation demo has been replaced. Its narrow decision-review engine is no longer the foundation of the studio.
